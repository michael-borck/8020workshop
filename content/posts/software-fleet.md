The printers and telescopes have jobs. The software does too, though it is harder to line up on a shelf.

I run a small game label called Retroverse Studios. The games are retro-style and pixel-art. *Reality Reigns* is a swipe-based decision game built on a configurable engine, so the same rules can carry a space, fantasy or educational theme. The Atari 2600 tribute series is four small games written as a nod to the hardware I grew up with. *LanePlay* is a tenpin bowling simulator that uses real PBA statistics to drive the simulated players.

Then there is the teaching work. I build small tools for educators and students: Curriculum Creator, Feed Forward, Talk Buddy, Study Buddy, Career Compass, Cite Sight, The AI Exchanger and The AI Skills Passport. They are deliberately narrow. Each one does a single job, because a tool with a settings page longer than its feature list tends to go unused.

The rest is open source. Python libraries on PyPI, npm packages and Docker Hub containers. Some of it supports the teaching tools, with shared utilities and deployment scaffolding. Some of it is standalone.

### The 80-20 take

Software is the one place where the 80-20 rule covers money and scope at once. The question at the start of a project is what the smallest useful version looks like: an engine that carries several themes, a tool with one job, a library that saves the same ten minutes on every project.
